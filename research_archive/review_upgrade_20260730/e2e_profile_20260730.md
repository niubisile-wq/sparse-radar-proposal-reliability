# Same-process batch-1 endpoint profile (2026-07-30)

The profiler loads primary and expert checkpoints in one Python process and
measures sequential primary H2D/forward, expert H2D/forward, and the gate/vote
endpoint on an RTX 4080 SUPER. Two warm-up samples are discarded.

| Dataset / seed | primary forward (ms) | expert forward (ms) | gate+vote endpoint (ms) | total endpoint (ms) | Hz | peak allocated (MB) |
|---|---:|---:|---:|---:|---:|---:|
| Astyx / 2027 | 8.74 | 6.71 | 0.05 | 16.08 | 62.2 | 197.0 |
| TruckScenes / 2027 | 11.06 | 10.42 | 0.08 | 23.11 | 43.3 | 197.9 |
| V2X-Radar-V / 2027 | 14.25 | 6.53 | 0.05 | 21.62 | 46.3 | 200.6 |

The reported endpoint numbers use the detector's returned post-NMS proposals
with the candidate-rich score/NMS settings used by the strict profiling
script.
The sampled outputs contained only 10--27 boxes, so the strict route's
50-entry residual exclusion removed all primary boxes in this direct endpoint
profile. Therefore these measurements are evidence for the real sequential
primary-plus-expert detector endpoint, but must not be described as a complete
candidate-rich 500-proposal strict-route FPS measurement. The separate
500-proposal voting-kernel profile remains the appropriate evidence for the
offline raw-proposal implementation.
